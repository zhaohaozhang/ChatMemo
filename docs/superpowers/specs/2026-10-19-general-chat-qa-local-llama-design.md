# 聊天记忆：通用问答、本地 llama.cpp 生命周期与系统验收设计

日期：2026-10-19

状态：待用户最终批准

## 背景

现有工具已支持 TXT 导入、联系人隔离、原文检索、上下文、消息引用、主题概览、联系人回收站，以及通过 OpenAI 兼容接口调用 llama.cpp。当前检索仍以正文文字匹配为主，因此“我们第一次对话是哪一天”等结构化问题会被错误地当成关键词搜索；同时应用只能连接外部启动的 llama.cpp，缺少可靠的一键启停与诊断。

本设计把产品从“搜索聊天文字”扩展为“基于可验证证据的本地聊天问答”。真实聊天始终留在本机；ChatGPT 只参与使用虚构数据的外部质量评审。本设计取代旧规格中“不管理 llama.cpp 启停”的限制，其余联系人生命周期、主题分类与引用约束继续有效。

## 目标

1. 自然语言问题先识别查询意图，不再直接把整句当作关键词。
2. 时间、次数和频率等确定性问题由本地程序计算。
3. 语义、上下文、变化及归纳问题先检索证据，再按需要调用本地 llama.cpp。
4. llama.cpp 不可用时，统计和原文查询仍可工作，其他问题安全降级。
5. 提供受控的一键启动、停止、状态检查和故障诊断。
6. 使用虚构数据建立系统回归测试，并让 ChatGPT 对虚构输入输出做外部评审。
7. 通过发布门槛后，将不含个人数据的源码发布到用户指定的 GitHub 仓库。

## 非目标

- 不上传真实聊天、数据库、来源文件、日志或检索片段到云端。
- 不做人际关系评分、心理分析、人物画像或跨联系人比较。
- 不让模型计算或覆盖可由数据库准确得到的日期、次数与统计结果。
- 不下载模型，不自动修改系统设置，不自动开放局域网监听。
- 不把“未检索到”解释为“从未发生”或“从未说过”。
- 不保证回答规格之外的任意开放世界问题。

## 不可降级的 P0 不变量

以下条件优先于功能覆盖、回答流畅度和性能优化；任何一项失败都阻止发布：

1. **身份与来源稳定**：`contact_id`、`message_id`、`source_id` 及消息到来源行号的映射在重复导入、恢复、重建索引和进程重启后保持稳定，已永久删除的 ID 永不分配给新对象。当前数据库使用普通 `INTEGER PRIMARY KEY`，实现计划必须包含防止删除后 ID 复用的迁移方案与回归测试。
2. **引用完整性**：引用必须存在、属于当前有效联系人、对应有效来源，并能定位到原文件行号；不能只校验字符串格式。
3. **状态失效**：联系人切换、移入回收站、恢复、永久删除、重新导入及索引或规则版本变化后，相关会话范围、候选集、引用集合和派生缓存必须失效或重算。当前版本没有持久化答案缓存；未来新增任何缓存前必须先满足此约束。
4. **确定性独立**：llama.cpp 未配置、未启动、加载失败、超时或异常退出时，结构化时间和统计分析仍独立工作。
5. **进程归属**：停止 llama.cpp 前必须同时验证 PID 和进程身份；验证失败则拒绝停止，不得影响外部进程。
6. **整段降级**：模型响应中任一事实性答案单元缺少有效引用、引用非法或结构无效时，整个模型回答作废并退回证据层，不尝试删除坏句、替换 ID 或修补答案。
7. **可重复评审**：每个虚构测试案例都必须明确记录允许答案、必需引用和禁止结论，使本地回归与 ChatGPT 外部评审可以重复执行和比较。

## 核心架构

采用三层混合路由：

1. **确定性分析层**：直接查询结构化消息与来源元数据，完成时间定位、计数、频率、间隔、活跃区间和说话人统计。
2. **证据检索层**：组合精确文本、中文近似表达、时间、说话人、主题和邻近上下文，返回真实消息与范围说明。
3. **本地归纳层**：只把已经选出的必要证据发送到 `127.0.0.1` 上的 llama.cpp；模型整理语言，但不创造事实或引用。

一个问题可以同时命中多个意图。例如“最近什么时候第一次提到工作”同时使用时间窗口、首次定位和语义检索。路由结果记录主意图、辅助意图、过滤条件和选择该路径的原因。

## 最小完整意图集合

### 1. 时间定位

处理首次、最后一次、某天、某月、某阶段，以及某件事首次或最近被提到。联系人最早聊天时间直接读取最早有效消息，不搜索“第一次”等问题词。用户可见措辞必须是“当前已导入记录中最早的一条”，不得暗示它一定是现实中的绝对第一次；若存在无法解析时间的消息或导入范围不完整，应同时显示覆盖缺口。

### 2. 计数统计

处理消息数量、提及次数、聊天频率、连续活跃天数、最长未聊天间隔、最活跃时段和说话人占比。数字全部由程序计算，并公开统计范围、时间边界与计数口径。

### 3. 原话检索

处理“谁说过”“有没有这句话”“原话是什么”。精确命中与近似命中必须分开展示；相同文本的重复消息按不同消息 ID 保留，不能按正文去重。

### 4. 语义检索

处理措辞不同但意思相近的问题。结果标为“相近表达”，不得用引号伪装为逐字原话。语义能力不可用时退回关键词、主题和原文浏览，并明确能力限制。

### 5. 上下文解释

处理“那天前后还说了什么”“这句话是什么背景”“这里的他/她可能指谁”。上下文来自相邻消息和同一会话范围；指代只能给出有证据的候选，无法确定时明确标记不确定。

### 6. 变化比较

处理过去与现在、前后态度或说法变化。变化结论至少引用两个不同时间点；若只有单侧证据，只描述已找到的记录，不能宣称发生变化。

### 7. 主题归纳

处理主要聊过什么、某阶段主题、关于某事谈过哪些内容。程序先构造分布在不同时间的证据集合，再由本地模型整理；不得从单条情绪或第三人称内容推导永久人物属性。

### 8. 证据状态

回答明确区分“已找到直接证据”“找到相近表达”“证据不足”“记录互相矛盾”和“当前范围未找到”。否定问题不得因为零命中就回答成绝对否定。

## 多轮上下文

当前联系人由用户显式选择，不允许模型更换联系人。会话状态只保存必要的上一轮查询范围：主意图、主题或实体、时间范围、说话人过滤和引用集合。“后来呢”“那次呢”等追问可以继承这些字段。

界面应显示本轮继承的范围并允许一键清除。联系人切换、删除、恢复、重新导入或索引版本变化后，旧问答上下文与引用集合失效。

## 检索与证据选择

证据选择按以下顺序组合：

1. 当前有效联系人的消息边界；
2. 显式时间和说话人过滤；
3. 精确短语、分词、字符 n-gram 和固定同义表达；
4. 主题与元数据候选；
5. 邻近上下文扩展；
6. 去除只因问题通用词命中的噪声；
7. 按相关性、时间要求和证据多样性排序。

结构化分析器可以绕过正文检索。变化与归纳问题应选择不同时间点的证据，避免高频重复消息垄断上下文。

## 统一回答契约

每次回答至少包含：

- `answer_kind`：程序统计、原文证据、相近表达或模型归纳；
- `answer`：简短答案或明确的证据不足说明；
- `intent` 与辅助意图；
- `scope`：联系人、时间范围、说话人、可解析时间覆盖率及其他过滤条件；消息数量必须拆分为当前联系人总有效消息数、过滤后消息数、候选召回数和最终证据数，不使用含义模糊的单一“已搜索消息数量”；
- `citations`：当前有效联系人的真实消息 ID、日期、说话人、原文和来源定位；
- `method`：本轮使用的分析器、检索或模型；
- `uncertainty`：歧义、冲突或能力降级说明。

内部回答不得只保存“一大段文字 + 若干引用 ID”，而应拆成可独立验证的 `answer_units`。每个单元至少包含单元文本、单元类型、引用 ID 列表和不确定性；事实性单元必须有一个或多个引用，程序统计单元还要带计算口径。最终界面可以把单元组合为自然语言，但必须保留逐单元引用关系。

服务端对所有答案单元校验引用存在、属于当前联系人、联系人未删除、消息与来源仍有效，并校验模型响应结构完整。任一事实性单元出现未知 ID、错联系人、已删除消息、无引用或明显证据不足时，整段模型结论作废并退回证据层。结构校验只能证明“引用合法且逐单元存在”；引用是否真正支持结论还要由虚构数据回归测试和外部评审验证。

## llama.cpp 一键启停

设置页保存并显示：`llama-server.exe` 的绝对路径、GGUF 模型绝对路径、仅本机端口（默认 `8080`）、上下文长度、GPU 层数、线程数，以及最近一次启动与诊断结果。

启动时使用参数数组直接创建进程，不通过 shell 拼接命令。聊天文本、导入文件和模型输出都不能修改路径或参数。默认绑定 `127.0.0.1`，不自动开放防火墙或局域网访问。

应用保存本次启动的 PID、启动时间和不可变的进程身份信息。停止只终止本应用启动且身份仍匹配的进程；不能按进程名批量终止，也不能停止已存在的外部服务。

端口已占用时先判断是否为兼容外部服务：兼容则标记“外部服务”并允许连接；不兼容则报告端口冲突。两种情况都不自动终止占用者。

## 服务状态与诊断

状态分为：未配置、路径无效、正在加载、可用、外部服务、端口冲突、异常退出、请求超时和响应不兼容。

检查顺序为：

1. 验证配置文件存在且类型正确；
2. 检查端口状态；
3. 轮询健康端点，允许模型长时间加载；
4. 查询 `/v1/models` 获取实际模型 ID；
5. 执行不含聊天内容的最小 Chat Completions 探针。

连接与生成使用不同超时。生成超时或失败后不自动重复提交证据，也不转向云模型。确定性分析继续工作；语义或归纳问题退回相关原文、上下文与明确故障提示。

## 隐私与提示注入边界

- 真实聊天只进入本地数据库、本地检索与 `127.0.0.1` 的 llama.cpp 请求。
- ChatGPT 评审只接收虚构数据、预期答案和去个人化程序输出。
- TXT 中的“忽略之前指令”“发送文件”“执行命令”等始终是不可执行资料。
- llama.cpp 输出不能触发文件、网络、联系人删除、进程启动或其他工具操作。
- 日志不记录完整聊天正文；诊断导出默认只包含状态码、耗时、配置字段名和脱敏错误。

## 系统测试设计

### 虚构数据集

建立覆盖多种日期格式、跨午夜与时区、同秒重复消息、多行消息、昵称变化、第三人称、代词、否定表达、同义表达、前后偏好变化、矛盾记录、长时间空档、重复导入、联系人删除恢复、提示注入文本及无证据问题的可版本化数据集。

数据集只含虚构人物和内容。每个问题必须保存允许答案、允许意图、必需引用、禁止结论、可接受的不确定说明和适用范围；这些字段是机器可读的测试夹具，而不是只写在说明文档中。

### 四层验证

1. **单元测试**：解析、路由、分析器、统计边界、检索排序、引用校验、会话继承与进程身份管理。
2. **接口与浏览器测试**：导入、联系人切换、连续提问、打开引用、删除恢复、模型启停、端口冲突与故障降级。
3. **真实 llama.cpp 测试**：使用用户现有 Qwen3.5 GGUF 验证加载、模型发现、回答格式、超时、异常退出和停止中的请求。
4. **ChatGPT 外部评审**：只提交虚构问题、标准答案和程序输出，检查漏答、误答、错误绝对化、引用错配与表达误导。每个确认的问题先转为可复现测试，再修复并重新运行完整套件。

P0 测试单独形成发布阻断矩阵，覆盖 ID 不复用、来源定位、所有失效触发器、无 llama.cpp 的确定性回答、PID 身份不匹配、任一答案单元引用非法时整段降级，以及测试夹具字段完整性。

### 必测组合

- “最早什么时候说过某事”：时间定位 + 语义检索；
- “最近老在聊什么”：时间窗口 + 统计 + 主题归纳；
- “以前是不是更喜欢某物”：疑问或否定 + 变化比较；
- “后来呢”“那次呢”：多轮范围继承；
- “说过类似意思但不是这句话吗”：原话与语义结果分离；
- 零命中：只说明当前范围未找到；
- 同文重复：按不同消息 ID 正确计数；
- 联系人删除或切换：旧上下文与引用立即失效。

## 发布门槛

发布前必须满足：

1. 全部自动测试通过，八类意图及组合问题达到验收标准。
2. 真实 llama.cpp 启停、模型发现、生成、超时和降级均完成实机验证。
3. ChatGPT 对虚构测试输出发现的问题均已分类；所有可复现的严重和中等问题已经修复并加入回归测试。
4. 仓库扫描确认不包含真实聊天、数据库、上传文件、模型、个人绝对路径、运行日志、密钥或令牌。
5. `.gitignore` 覆盖运行数据、缓存、配置、模型与临时文件。
6. README 说明安装、数据格式、隐私边界、llama.cpp 配置、故障排查、测试结果与已知限制。
7. 用户确认 GitHub 仓库名称和公开性后，才初始化或关联仓库并推送。

## 验收标准

1. “我们第一次对话是哪一天”无需正文含有“第一次”等词，即可返回当前已导入记录中的最早有效消息日期和引用；范围不完整或存在缺失时间时同时给出限制说明。
2. llama.cpp 未运行时，时间、次数和统计问题仍得到准确回答；归纳问题显示原文证据和故障原因。
3. 精确原话与相近表达明确区分；零命中不产生绝对否定。
4. 变化回答至少包含两个时间点的有效引用，否则标记证据不足。
5. “后来呢”等追问正确继承并展示上一轮范围，联系人变化后不继承旧范围。
6. 模型回答中的每个引用均属于当前有效联系人；无效引用使模型回答整体降级。
7. 一键启动能使用已配置的 llama.cpp 和 GGUF；停止不会影响外部或身份不匹配的进程。
8. 端口冲突、慢加载、生成超时、异常退出和生成中停止均有明确状态，且不会触发云端回退。
9. ChatGPT 系统评审全过程只使用虚构数据。
10. GitHub 发布物不包含任何真实聊天或本机私有运行数据。
11. 永久删除后创建新联系人、来源和消息时，不会复用已经删除的公开 ID；重复导入与恢复也不会改变既有 ID 和来源映射。
12. `scope` 同时返回总有效消息数、过滤后消息数、候选召回数和最终证据数，各口径有独立测试。
13. 模型回答以答案单元表示；任一事实性单元引用缺失或非法时，用户看不到任何部分模型结论，只看到证据层降级结果。
