# 拾忆 · 聊天记忆

一个在本机运行的 TXT 聊天资料库。它按联系人保存原文与来源，可回答时间、数量、原话、上下文、变化和主题等问题；每个事实都可以回到原消息核对。

默认流程不需要模型。可选的 llama.cpp 只接收已经在本机召回的必要证据，回答请求只允许发往 loopback 地址，不会自动改用云服务。

## 快速启动

需要 Python 3.11 或以上，无第三方 Python 依赖。在项目目录运行：

```powershell
python server.py
```

然后打开 <http://127.0.0.1:8765>。Windows 也可以运行 `start.ps1`。按 Ctrl+C 停止服务；端口被占用时可运行 `python server.py --port 8766`。

服务只监听 `127.0.0.1`。首次体验可点击“试用虚构示例”，或导入 `examples/小林-虚构示例.txt`；示例中的人物和内容均为虚构。

## 导入与联系人

1. 点击“＋ 新建联系人”建立独立空档案，或直接点击“导入聊天记录”选择 TXT。
2. 在预览中核对时间、说话人、多行正文和解析警告。
3. 导入默认新建联系人，不会暗中追加到当前联系人。要追加到既有档案，必须在“保存到”中明确选择并核对归属提示。
4. 同名联系人保持独立；导入同一文件到同一联系人不会重复增加消息。
5. 如果回收站中有同名档案或同一文件，必须明确选择恢复、仍作为新联系人导入或取消。
6. “移入回收站”会立即让该联系人从问答、主题、导出和模型证据中消失；恢复保留原 ID。永久删除必须输入完整联系人名称，且不可恢复。
7. “导出 Markdown”生成可手动放入 Obsidian 的原文文件，不会自动修改现有 Vault。

## TXT 格式

每条消息以类似下面的行开始，直到下一条时间行之前的换行都会保留在正文中：

```text
[2026-09-01 18:00:00] 小林: 第一行
第二行仍属于同一条消息
[2026-09-01 18:05:00] 我: 收到
```

也支持不带方括号的时间、中文冒号、消息类型标记、UTF-8、GB18030 和带 BOM 的 UTF-16。单文件上限 5 MB / 30,000 条。图片、语音和视频占位符按原样保留，不做媒体识别。无法识别的内容会在预览中列出，不会被偷偷改写。

## 证据问答

“证据问答”会先做本地路由和检索，覆盖八类意图：

- 时间定位：第一次、最早、最后一次、哪一天；
- 数量统计：消息数、活跃日期、最长间隔等；
- 精确原话：逐字引用、谁说过某句话；
- 语义检索：相近表达、与某件事相关的记录；
- 上下文解释：前后发生了什么、代词可能指谁；
- 变化比较：以前和后来是否出现不同说法；
- 主题总结：主要聊过哪些主题；
- 证据状态：当前范围能否支持某个结论。

一个问题可以同时触发多个处理器，例如“最早什么时候提到工作？后来怎么样了？”会组合确定性时间与相关证据。简短追问如“后来呢？”会使用上一轮识别出的主题实体补充本地检索；时间表达和说话人会保留在上下文中供展示，但不会暗中替代页面筛选。日期、说话人范围始终以当前可见控件为准。

联系人切换、移入回收站、恢复、任何重新导入或规则版本变化都会使旧问答上下文失效，防止旧范围混入新答案。

时间、计数和边界类问题由本地确定性代码计算，即使 llama.cpp 完全不可用也能回答。检索没有命中时只会说明“当前筛选范围内未找到”，不会据此断言现实中从未发生。

### 引用与范围数字

回答被拆成独立的答案单元。每个事实性单元必须有自己的 `[M数字]` 引用；任一单元引用不存在、属于其他联系人、已回收或不在本次证据中，整段模型答案都会废弃并降级为本地证据结果，不会尝试修补模型文字。

结果下方分别显示：

- 联系人总量：该联系人当前有效消息总数；
- 过滤后：日期与说话人筛选后的消息数；
- 候选：本地召回规则命中的消息数；
- 送入整理：包含必要上下文、实际交给整理器的消息数；
- 最终引用：最终答案真正引用的不同消息数。

点击“查看原文”可核对说话人、时间、文件名、原始行号和前后消息。

## llama.cpp 一键配置

模型不是必需项。要启用本地整理：

1. 先准备 `llama-server.exe` 和兼容的 `.gguf` 模型。
2. 打开“本地 AI 设置”，填写两个文件的绝对路径，并按硬件调整端口、上下文长度、GPU 层数和线程数。
3. 点击“保存并启动”。应用使用参数数组固定启动 `llama-server.exe`，绑定 `127.0.0.1`，等待模型可用后从 `/v1/models` 读取真实模型 ID。
4. “探测本地服务”只发送固定的 `Reply with READY.`，不发送联系人、问题、文件名或聊天记录。
5. 提问时只有本地检索已召回证据才会交给模型；模型超时、停止、格式错误或引用校验失败时，页面返回本地证据降级结果。

启动配置保存在 `runtime/llama.json`，只包含可执行文件路径、模型路径和启动参数；不保存聊天正文、API 密钥或模型答案。`runtime/` 已被 Git 忽略。

如果配置端口上已经存在兼容的本机服务，应用会将它标记为“外部服务”并使用，但绝不会停止它。停止按钮只对本应用启动、且当前页面持有匹配 owner token 的同一进程句柄有效；仅有 PID 或相同端口不足以结束进程。

### llama.cpp 故障排查

- “路径不存在”：确认填写的是 `llama-server.exe` 文件和 `.gguf` 文件，不是目录。
- “端口被非兼容服务占用”：换一个 1024–65535 的空闲端口，或先自行处理占用程序。
- 长时间显示“正在加载模型”：减小上下文长度或 GPU 层数，检查模型是否适合可用内存，然后再次探测。
- 页面刷新后停止按钮不可用：重新点击“保存并启动”可重新取得当前由本应用管理进程的所有权令牌；外部启动的进程仍需在其原启动位置停止。
- 探针成功但问答降级：模型必须支持 OpenAI 兼容 Chat Completions 和严格 JSON Schema；查看原文证据是否足够，并检查模型是否在 60 秒内返回。
- llama.cpp 完全不可用：继续使用时间、计数、原话检索、主题概览和证据列表；系统不会转发到云端。

## 数据、备份与隐私边界

`data/memory.sqlite3` 保存联系人、原始文件字节、消息正文和来源映射。备份前先停止服务，再复制整个 `data` 文件夹。

应用不会借用浏览器中登录的 ChatGPT，也不会自动向 ChatGPT 或其他网页发送聊天记录。开发时与 ChatGPT 的系统测试仅使用仓库中的虚构数据。携带聊天证据的模型请求只允许发送到 `localhost`、`127.0.0.1` 或其他 loopback 地址。

正文按纯文本显示；导入内容被视为不可信数据，其中写着的指令不会执行。模型没有工具调用能力。发布扫描会阻止数据库、GGUF、日志、密钥、本机配置和常见绝对私有路径进入发布候选。

## 已知限制

- 目前面向带时间和说话人的 TXT，不直接读取微信数据库、图片内容、语音或视频。
- 语义召回是可解释的本地规则与主题同义词扩展，不是向量数据库；表达非常隐晦时可能漏检。
- 变化比较要求至少两个不同时间点的相关证据；证据不足时会明确保留不确定性。
- 代词、第三人称和“现在是否仍然如此”不能仅凭旧聊天可靠确认，系统应引用原文并说明范围，而不是推断人物现状。
- 本地模型质量取决于 GGUF、提示词兼容性和硬件；模型答案始终需要结合引用原文核对。
